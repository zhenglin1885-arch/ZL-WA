# 账号右侧工具

本轮基于 Ferdium v7.2.3 增加代理、翻译和批量发送，保留原有分组、备注、会话菜单和手动休眠。点击右侧「代理」「翻译」展开当前 WhatsApp 账号的独立设置，再次点击当前工具按钮恢复主会话宽度；「群发」在主窗口正中打开任务窗口。

## 代理

- 每个 WhatsApp 账号使用 `persist:service-账号ID` Session，首次导航前等待代理初始化；应用代理时关闭旧连接并刷新该账号，不清除登录数据。
- 支持手动 HTTP、HTTPS、SOCKS5（含用户名密码认证），以及跟随系统代理。关闭开关后使用系统默认网络环境，不沿用之前的账号代理；配置方式仅保留手动配置与自动（系统代理），移除重复的「直接连接」。旧版直接连接设置会转换为关闭代理，保留已填的手动参数。
- 智能填写支持 `主机:端口`、`主机:端口:用户名:密码`、带认证信息的代理 URL 和 `[IPv6]:端口`。识别后需点应用。
- HTTP/HTTPS 认证只提供给该账号实际配置的代理主机和端口。带认证的 SOCKS5 使用每账号独立、仅监听本机的 CONNECT 桥接；桥接完成 SOCKS5 认证并由上游代理解析目标域名。关闭、修改代理或退出应用时释放桥接和旧连接；认证失败不会回退直连。
- 「应用并测试连接」会保存并应用表单，再使用该账号 Session 请求 WhatsApp 首页，显示实际代理路线和耗时。测试失败不表示已经登录；代理可能无法访问 WhatsApp。
- 密码通过 Electron `safeStorage` 加密保存，不返回界面。已保存密码的输入框留空表示保持，点「清除已保存密码」后应用才会删除。Windows 使用系统安全存储；安全存储不可用时拒绝保存密码，不降级为明文。代理 URL/智能填写中的密码在识别后从粘贴框清除。

不提供指纹伪装或协议号登录；参考图中的这两个标签不属于本轮代理配置范围。

## 翻译

每个账号独立设置发送/接收开关，两种方向分别选择通道、源语言和目标语言。提供 Google 免 Key、DeepL API Free、OpenAI、Gemini，以及保留的 LibreTranslate 通道。Google 免 Key 通道为非官方接口，可用性和额度不作保证；DeepL 官方 Free API 仍需自行申请 API Key，不内置共用密钥。OpenAI、Gemini 使用用户自己的 Key 和可配置模型，费用和额度取决于各自账号。Key 通过系统安全存储加密保存，界面只返回是否已保存，不返回原 Key。留空保留，清除按钮在应用后删除。

翻译请求使用当前账号的 Session/代理。点击「应用并测试发送翻译」或「应用并测试接收翻译」，只翻译内置测试句，不发送 WhatsApp 消息；失败显示连接、权限或额度提示。启用自动翻译后，消息文字会提交给所选第三方。

**发送翻译流程：**

1. 开启发送翻译，选择语言并应用。
2. 在 WhatsApp 文字输入框输入原文，点击发送或按回车。纯表情（含图片装饰节点）、数字、符号和纯链接不调用翻译，第一次发送即可按原样发出；图片／视频预览中的说明文字也遵循两步发送流程：首次发送先翻译并替换说明，用户校正后再发送媒体。空说明与纯表情说明不翻译；贴纸和无文字附件保持 WhatsApp 原生发送方式。
3. 第一次发送被拦截，原文不会发送；译文成功后，先校验原草稿和聊天身份，再通过原生全选快捷键完整选中并校验富文本内容，随后使用 Electron 原生 `insertText` 写入编辑器，写入成功后才允许第二次发送。不再依赖网页的 `execCommand`，以兼容受控编辑器。
4. 用户校正译文，第二次点击发送或按回车，才由 WhatsApp 原有发送流程发出。

等待译文期间重复点击、长按回车、双击按钮都不会自动确认。请求失败时保留原文并提示；如果原文被修改、切换聊天、页面重载、设置变化或账号休眠，旧请求不会替换新的草稿。开启翻译后不提供失败时自动发送原文的回退。

**接收翻译与预览：**

- 翻译开关开启后立即保存并生效。开启「接收翻译（收发消息）」后，当前聊天已加载的收到/发出的文字消息下方都显示蓝色「点击翻译」按钮。此时不自动提交消息文字；点击后使用接收翻译通道、源语言和目标语言翻译，译文在原消息下方显示，不重发消息。
- 开启「翻译预览」会同时开启接收翻译，不立即批量处理当前聊天；从下一个打开的聊天开始，等待页面初始定位后，只分批翻译可见区域及少量临近的收、发文字消息。向上查看历史时再按需处理，不一次翻译整个已加载历史。失败或暂未翻译的消息保留「点击翻译」按钮，可逐条手动重试。自动失败不会无限重试请求。
- 关闭接收翻译会同时关闭预览并移除按钮、译文；重新打开后可再次翻译。目标语言/通道变化会重新生成预览。
- 仅处理文字正文及文字说明，不翻译语音、图片本身、文件内容、已删除消息、引用预览或未打开聊天的后台消息。保留原文，不修改或重发已发送消息。
- OpenAI、Gemini 的 API Key 配置入口始终显示；选择对应通道时展开密钥和模型设置。Key 需用户自行填写，测试按钮会明确提示缺少 Key，不内置共用密钥。

消息识别同时支持语义正文标记（如 `data-pre-plain-text`）和传统消息结构，不要求固定类名或固定消息 ID 前缀。面板提供「检查页面识别」及「复制页面诊断」，显示已识别消息、译文和待处理数量；复制内容只含结构、状态与计数，不含消息正文、属性值、号码或 API Key。原生替换后若内容不符，会停止对同一草稿重复替换，避免越点越追加。

选择 Google 时，主进程会优先使用 Google。遇到限流、临时繁忙或连接失败后自动调用免 Key 的 MyMemory，沿用当前账号代理，不新增前端通道、密钥或其他配置。Google 冷却期间的新请求直接使用备用通道，冷却到期后下一次未缓存请求优先尝试 Google，成功后恢复主通道。MyMemory 的源语言在本机识别，长文本按 UTF-8 字节限制分段并保留换行；任何分段失败都不会提交部分译文。两个通道均不可用时保留原文并提供重试，不自动发送原文。MyMemory 自身也有免费用量限制。成功译文沿用原有持久缓存规则，Google 与 MyMemory 的成功结果都会保存并复用，不因冷却结束、刷新页面或重启而重新请求。仅手动重新翻译、翻译配置变化或原有容量淘汰规则会触发相应重新请求；未缓存的新内容仍优先尝试可用的 Google。

翻译请求最多同时处理 3 个账号，每个账号同时 1 条，自动预览最多挂起 2 条，发送预览优先，主通道单次请求设有 20 秒超时，MyMemory 每段 12 秒、整条最多 60 秒，并限制分段请求频率；队列和缓存有上限。成功译文分为当前页面的快速缓存和 profile 下 `translation-cache.json` 的持久缓存。持久缓存按账号、通道、源／目标语言、模型与凭据配置区分，最多 3000 条且译文正文总大小最多 5 MB，达到上限逐条淘汰旧项。原文与凭据只用于散列键，不写入缓存；缓存文件本身包含译文，属于本地应用数据。退出时刷新，重启后仍可复用成功译文，失败不缓存；删除账号会移除其缓存。原有右键手动翻译功能仍可使用。

只轮询当前选中的 WhatsApp 账号，后台账号不扫描消息。只在消息／滚动变化或低频兜底检查时识别可见消息。翻译附加内容改变高度时，原本在底部就保持底部；阅读历史时保留可见消息的位置，不持续强制滚到底部，也不改变 WhatsApp 自身的未读定位。

## 批量发送与撤回

记录和新建窗口覆盖 WhatsApp 页面，随窗口尺寸调整，标题和底部按钮固定，中间内容滚动。新建页面为「选择账号／群发对象／群发设置」三栏，窄窗口改为两列或单列。

1. 勾选在线且未休眠的账号，点击「读取聊天对象」。账号支持名称、手机号、备注搜索，并显示头像、昵称、号码、备注。对象只来自所选账号，可以按全部、群聊、私聊、通讯录、已归档、所属账号及名称／ID 筛选。同名对象在不同账号下独立计数。
2. 支持文本、图片、图文（图片及说明）、视频、语音（上传语音文件，以 PTT 形式发送）、名片（姓名及含国家区号号码）、文件。附件通过系统文件选择框选取，复制到当前 profile 的 `bulk-media`，避免定时发送时源文件移动而丢失；单文件上限 50 MB，平台可能有更严格的格式或大小限制。
3. 每个任务发送一条内容，可设置立即发送或本机时间定时发送、固定／随机聊天间隔（0.5–3600 秒）、发送前输入状态时长（0–30 秒）、遇到失败停止或跳过失败继续。文本、图文、视频及文件说明可在群聊中 @所有人，按实际成员 ID 生成提及，私聊不提及。名片、纯图片、语音不提供 @所有人。
4. 点击「检查并发送」核对消息类型、附件、对象数量、时间和策略，再确认。群发正文按原样发送，不使用聊天输入框翻译。不会自动切换用户正在阅读的聊天。同步发送和文件文本不包含在本轮。
5. 定时任务保存到本机；软件运行期间到时执行，账号必须在线。关闭窗口后任务继续，退出软件则停止执行。重新启动后，未来的定时任务继续等待；已错过的任务标记「已错过」，发送中断的任务标记「已中断」，不会自动补发或重试。取消定时任务后才可删除其记录。
6. 记录服务器接受数量、失败／未确认数量及每条消息编号。服务器接受不等于收件人已读。发送返回编号但回执尚未同步时，先按原编号短暂只读核验，不重发。选择继续时，有编号且请求已返回的待确认项保留记录，继续其他对象；选择停止或缺少编号时停止。120 秒未返回发送结果时停止整个任务，即使选择跳过失败也不会继续，以免不确定请求持续扩散。停止操作等待当前操作返回，随后跳过剩余对象。

群发设置修改后自动保存，关闭并重新打开窗口或重启软件后恢复消息类型、立即／定时模式、固定／随机间隔、输入状态、@所有人、失败策略和对象类型筛选。收件人、正文、附件和具体定时时刻仍需每次核对／选择，不由记住设置触发发送。

记录页按内容、状态、日期搜索，支持重置、分页、详情、再发一条、更多操作和清空记录。「再发一条」带入原任务供重新编辑，仍需再次确认，不直接发送。

「更多 → 撤回已发消息」中选择具体聊天并确认，会请求**对所有人撤回**保存编号的消息；撤回前检查消息属于当前账号及记录的聊天。结果在详情及「撤回记录」中显示，平台时限、权限或接口变化可能导致失败。已撤回的消息不会再次提交撤回；撤回超时停止剩余撤回操作。缺失消息编号且保留发送任务信息的记录会先只读核对，再对唯一匹配、属于当前账号及聊天的消息开放操作；不会补发消息。无法唯一匹配时显示原因，只有编号且缺失旧任务信息的记录仍可由页面验证权限后编辑。

「删除记录／清空记录」仅删除本机任务记录，**不会撤回 WhatsApp 消息**。附件副本保留在 profile 的 `bulk-media`，删除记录不会删除可能被其他任务复用的附件。多媒体、通讯录、输入状态和撤回使用随安装包固定的 WA-JS 4.7.1（Apache-2.0，许可证随包分发）；若 WhatsApp 更新导致接口未就绪，会显示失败，不假报发送或撤回成功。

## 保存位置及验证边界

配置和最近 100 个发送任务保存在当前 ZL-WA profile 的 `account-tools.json`。代理密码和翻译 API Key 为系统加密值；发送记录含正文和对象名称，属于本地应用数据。删除账号会移除其工具配置和代理凭据，保留发送历史供核查。切换账号不会把一个账号的表单应用给另一个账号。

软件新建本地用户及登录页默认简体中文，WhatsApp 会话的浏览器首选语言为简体中文。已手动选择的应用/WhatsApp 账号语言可能继续沿用原偏好，可在其设置中切换；更新不清除账号登录数据。

本次修复分组、备注等弹窗被全局高度样式挤出屏幕的问题，回归用真实鼠标/文字输入和屏幕内坐标验证显示与保存。

本轮在 Linux 云环境实际启动 Electron，用本地模拟 WhatsApp 网页和翻译响应验证窗口操作、收发翻译状态机、代理 Session、真实本地 CONNECT/TLS 连接、文字及多媒体发送适配器、文件选择／复制、消息撤回记录、多账号失败停止及取消。模拟测试不代表已向 WhatsApp 服务器发送成功。

WhatsApp 的内部网页接口和编辑器可能随官方更新变化。仍需 Windows 扫码后验收真实昵称/头像、真实代理认证、第三方翻译服务连通性、编辑器替换及收发行为；已生成 Windows x64 测试安装包和便携 EXE，仍需真实 Windows 实机验收。

## TEST8：本地置顶、客户资料与未读数

右侧原「收起」按钮改为「客户」。先打开私聊联系人，再点「客户」查看该联系人的资料；群聊不显示客户表单，但仍保留聊天列表快速备注。面板关闭后再次打开会加载本机保存的内容。资料按已登录的真实 WhatsApp 账号和聊天标识区分；重新创建软件会话后登录同一 WhatsApp 账号，仍可读取当前电脑中保存的资料，不通过 Ferdium 云端同步。

- 使用 WhatsApp 聊天菜单中的「置顶聊天 / Pin chat」「取消置顶 / Unpin chat」。置顶直接显示在原生聊天列表中，沿用原生图钉和菜单，不再添加悬停按钮或独立置顶区域。无 3 个数量限制，最新置顶排最上方，新消息不改变顺序。已有本地置顶保留，首次接入时合并官方已有置顶，此后以本地记录为准，避免取消后重启又恢复。只改变本软件的原生模型显示，不调用服务器置顶接口。备注名可在私聊客户面板或列表行内输入框中编辑，列表保留红色备注。

### Windows 验收

1. 从原生聊天菜单置顶 4 个以上群聊或私聊，确认新置顶在原列表最上方且显示原生图钉，来消息及滚动重建后顺序不变；取消置顶后应恢复普通排序，重启后不应重新置顶。确认没有额外「置顶／备注」按钮和置顶区域。
2. 编辑红色备注名，多选四个标记，填写长备注；快速切换两个聊天，再退出软件（包括托盘）并重新启动，检查资料是否保留且无串号。
3. 换一个 WhatsApp 账号打开相同号码的聊天，确认不会读取前一账号的客户资料。
4. 对未静音私聊发送 3 条、群聊发送 2 条消息，账号卡片应累计 5；归档或静音聊天的新消息不增加计数。

自动测试使用本地模拟页面，不连接真实 WhatsApp 账号，也不发送真实消息。WhatsApp 页面更新可能影响列表识别，Windows 和真实账号上的最终表现需要安装此测试包验收。

## 7.2.5：ZL-WA GitHub 更新入口

「设置 → 更新」显示 ZL-WA 当前版本和本项目 GitHub Releases 链接。开启自动更新时自动检查并显示新版本提示，关闭后仍能手动检查。检查只访问本项目，安装版及便携版都可使用。更新说明也从本项目读取。

## 7.2.6：修复图文说明的发送翻译

此前发送翻译只识别聊天底部输入框，图片预览中的说明文字会绕过翻译。现在媒体预览中的说明也会使用当前账号的发送翻译通道及目标语言，首次发送先替换为译文，不发送图片；校正后再次发送才提交图文。预览内的发送按钮与回车均支持。后台聊天草稿不被替换。

翻译失败时保留说明原文，不发送媒体；翻译过程中切换聊天、关闭预览或更换图片时丢弃旧结果。空说明、纯表情、数字或纯链接不调用翻译，保持原生发送。本轮修复作用于原生媒体预览的说明输入框，不对图片中的文字做 OCR；群发仍按任务正文原样发送。

## 7.2.7：视频和文件的附带文字

## 7.2.8：顶部账号网络状态

- Windows 主窗口顶部右侧显示当前启用且未休眠 WhatsApp 账号的出口 IP、延迟（ms）与刷新图标。切换账号时同步切换检测，不显示其他账号的旧结果。
- IP 通过当前账号的 Session / 代理访问 Cloudflare trace 获取；延迟是同一路由到 WhatsApp 的 HTTPS HEAD 请求耗时，不是 ICMP ping。开启账号代理时不得回退到系统直连 IP。关闭账号代理则遵循系统默认网络环境。
- 切换账号、修改代理和点击刷新图标时检测；驻留账号每 60 秒更新。短时间切换账号可复用 30 秒内的检测结果；手动刷新强制重测，合并并发请求。每个请求 12 秒超时。
- 检测失败显示「—」，悬停查看原因；IP 和延迟独立显示成功结果，不把失败显示为 0 ms，也不保留旧 IP 冒充当前连接。刷新仅检测网络，不刷新 WhatsApp 页面。检测结果不写入本地资料文件。
- 随 7.2.8 一并打包；真实账号、代理与 Windows 通知行为仍需安装后验收。

## 7.2.8：群发结果核对与编辑

- 修复将 WhatsApp 的 `OK` 发送结果误判为失败的问题，同时兼容 `success` 与真实 ACK（>=1）。普通文字发送在回执未知、回执异常或等待超时时仍返回已经分配的消息编号；只记为「待确认」，不自动重发。记录分别显示成功、待确认和失败数量。
- 「更多 → 核对发送结果」只读取原账号和原聊天。优先按已有编号核对；旧版缺编号时，只在最近 200 条消息中按本人发送、原聊天、精确正文/类型和任务发送时间窗口寻找唯一匹配。空正文附件还必须匹配文件名和大小；多个相同候选或找不到时保留提示，不猜测、不重发。
- 唯一匹配后保存消息编号、ACK 状态及核对时间；服务器已接受的记录修正成功数并恢复撤回能力。撤回仍受平台权限与时限限制，不以截图或正文看起来相同作为撤回依据。
- 单条任务的「删除记录」改为「编辑已发消息」。先选择聊天对象和更正文字，再确认。直接调用 WhatsApp 编辑接口修改原消息的文字或附件说明，不采用删除重发，不修改附件本体。语音、名片等不可编辑类型不提供入口；实际编辑能力以平台检查为准，通常仅允许原消息发送后 15 分钟内编辑。
- 每个对象独立记录编辑请求、成功后的文字/时间和异常，部分失败不冒充全部成功。原始内容保留用于核查；全部对象同内容更正成功后列表显示更正内容，部分更正显示计数与逐条详情。旧消息超出编辑时限时仍可在平台允许的范围内尝试撤回；不能突破官方编辑时限。
- 「清空记录」仍只清理本地任务历史，保留记录容量管理；编辑与核对均不触发新消息发送。
- 验证包括原生 `OK`、嵌套结果、未知/超时回执保留编号、唯一匹配/歧义保护、核对后撤回、原消息编辑及时间/归属/类型保护。`scripts/verify-bulk-corrections-ui.mjs` 使用隔离队列验证五条误报修复、编辑对象选择与部分失败、找回编号后的撤回，不向真实账号发消息。

- 始终显示手动暗色开关。手动切换会关闭同步系统；重新开启同步系统会清除手动强制暗色。用户主动开启通用暗色兼容时也会启用软件暗色，避免在浅色系统下无任何效果。兼容旧版本已保存的手动暗色偏好。
- 软件启动及设置变更时统一 Electron 的 dark/light/system 主题来源，MUI 使用实际主题；不改变电脑系统主题。
- WhatsApp 页面在当前软件会话内同步 html/body 的原生暗色/浅色类和已有主题属性、color-scheme，并监听原生页面延迟恢复浅色的情况。保留其他类和样式、不修改 WhatsApp 账号主题偏好、不调用需要刷新页面的主题 API；不刷新或重建会话，保留输入草稿。单个服务原有暗色偏好继续保留。
- 在浅色桌面的真实 Electron 进程中验证设置开关、软件主题、MUI、宿主及 guest 的 prefers-color-scheme；模拟 WhatsApp 原生主题 CSS 验证手动暗色、延迟浅色覆盖后的恢复、跟随系统切回浅色和未发送草稿保留。该模拟页面不等同于真实 WhatsApp 登录会话验收。

## 发送故障诊断

在原故障账号右侧「翻译」或「代理」面板点击「检查并复制发送诊断」，然后粘贴诊断文本。检查本身不会应用表单、切换代理、发送消息、刷新页面或清理登录数据；无需打开控制台。

报告包含软件与浏览器版本、WhatsApp/适配库版本（可读取时）、当前连接和同步状态，以及最近最多 200 条已加载消息中本账号发送消息的 ACK 分类计数。不包含消息正文、消息编号、聊天标识、账号号码、代理地址或密码。无法读取的状态标记为未知，不推断为连接成功或失败。

聊天列表仍显示不代表连接已恢复：已知 Socket 尚未连接或适配库报告主会话尚未同步完成时，账号保持加载状态。浏览器同账号发送正常也不足以确定软件原会话的故障原因；新建会话的历史、同步和设备状态不同，不能仅凭新会话成功就断定应清理原会话。
