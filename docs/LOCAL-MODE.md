# ZL-WA 本地模式

应用的账号管理、服务配置和工作组固定使用本机数据库与本机 API。首次运行自动建立本地会话，不需要注册、登录 Ferdium/Franz 或选择服务器。旧配置里的远程服务器地址会自动改为本地模式，不删除已有本地数据库、账户分组、备注或浏览器登录分区。

“可用的服务”只保留 ZL Picks 推荐页，保留原推荐服务（延续排除 Teams）；移除“所有服务”、自定义服务添加页面、开发文档/目录按钮和“服务丢失？”反馈入口。旧 all/dev 链接跳转到已有账号列表；列表的新增入口直接添加 WhatsApp。设置侧栏移除“您的工作组”入口，既有工作组数据和运行逻辑保留。安装资源只保留推荐服务的元数据、图标及完整插件，不访问上游服务目录或插件 CDN。已有账号、用户缓存及已安装插件继续读取原有数据，右侧“客户”资料功能保留。上游 recipes 子模块源码保留用于维护，非推荐服务不再进入应用构建资源。

账号、团队、邀请与切换服务器页面的旧链接会跳转到本地界面。设置侧栏显示“本地模式”。诊断功能改为保存本地 JSON 文件，取消向 Ferdium 调试服务器上传，并排除账户栏资料。

这不等于软件完全离线：WhatsApp 等服务自身、GitHub 在线更新、Cloudflare IP 检测、用户启用的翻译或待办服务仍会按对应功能联网。翻译引擎仍包括用户可选的 Ferdium LibreTranslate，此次修改不改变已确认的翻译配置。上游开源许可及署名继续保留。

仅存于旧云账号、从未保存在本机的数据，不能凭空恢复到本机；如有需要，应通过已有的本地文件导入方式恢复备份。应用不会为迁移而自动登录远程服务器。

验证：

- 单元测试覆盖旧服务器配置忽略、禁止远程账号请求、本地目录和图标、令牌入口和关闭远程导入路由。
- Electron 界面回归覆盖既有账户、未读、备注、翻译、代理、群发及群组工具。
- 隔离配置下阻断外部 HTTP 请求后，验证首次自动进入、本地服务添加与工作组创建；重启前写入旧 Franz 地址，再验证账户 ID、备注、分组和工作组保留。
- 此验证使用模拟 WhatsApp 页面，不代表真实平台操作验收。

开发验证脚本 `scripts/verify-local-mode-ui.mjs` 仅应在 `/tmp/zl-wa-local-mode-qa/` 隔离配置运行；它会创建停用的测试账户、工作组和备注，使用 `--restart` 验证持久化。

资源与入口校验：先运行 `node esbuild.mjs`，再运行 `node scripts/verify-zl-picks-resources.cjs`；启动开发版后运行 `node scripts/verify-removed-service-catalogue-ui.mjs`。后者检查 ZL Picks、旧链接跳转、工作组入口隐藏、WhatsApp 新增表单和已有账号保持不变，不创建账号。
