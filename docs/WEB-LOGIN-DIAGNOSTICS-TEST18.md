# ZL-WA 7.3.9 test18 · 原网页登录诊断

本轮只补充登录观察与脱敏诊断，尚未证明能修复用户账号的关联失败。继续使用原 WhatsApp 网页；不加入新连接界面或额外登录窗口，不修改已验证功能的业务逻辑。

## 使用

完全退出 ZL-WA 后安装测试包，在原账号里正常扫码或使用官方电话号码入口。如果手机提示无法关联或软件返回二维码，不要手动刷新；立即打开右侧“代理”面板，点击“检查并复制发送诊断”，将完整日志发回。无需使用 Console。

新版连接诊断 `connection.format` 为 4，包含通行密钥原生事件、连接关闭分类、官方通行密钥界面阶段和 `linkEventsObserved`。事件历史在同一账号页面导航后仍保留；各账号隔离，最多保留 64 条。网页未提供原因或提供未知类型时，仍如实记录 `null`，不猜测原因。

## 本轮范围

- 监听官方已初始化的 `WAWebLinkDeviceEvents` 中通行密钥请求、prologue 已发送、验证就绪和错误事件。
- 官方通行密钥界面可能自行捕获异常；只读取其固定 testid 对应的提示、处理中、等待手机、验证、失败等阶段，并在导航前保留阶段变化。不会读取错误消息或验证码文本。
- 保留 `WASocketCloseReason.CommsCloseReason` 的 22 个公开分类；错误只记录已知异常类名。
- 检查浏览器是否暴露 PublicKeyCredential 和 credentials.get；这两个布尔值不代表认证一定可完成。不会自行调用认证接口，不创建或读取通行密钥。
- 不读取验证就绪事件附带的验证码、挑战或凭据；不导出号码、聊天、Cookie、密钥、原始错误消息或服务器原始载荷。
- 不替换 WebSocket、fetch、存储、浏览器历史、credentials.get 或官方原生模块，不主动刷新、不自动重试关联。
- 原聊天界面、群发 D→C→B→A、默认 Enter/可选 Shift+Enter、翻译、昵称/备注、群管理和队列逻辑保持 test17 原样；应用 SDK 和依赖未升级。

## 依据与验证界限

官方公开登录页已包含这些原生事件。受控测试使用可追溯的公开模块定义，验证真实编译后的观察函数、隔离桥、日志脱敏及导航后保留；不使用真实手机、账号或认证资料。

通行密钥是待核实的原因，不是本次已确认根因。此前 Baileys 探针成功与当前日志缺少通行密钥请求，都意味着不能直接套用其他项目的诊断结论。

这是独立、未签名的 Windows 诊断测试包，不是正式更新，不覆盖历史 Release 资产，不发布 Mac。
