# 7.3.9 功能兼容检查

本次包含前次 FB 与群组身份检查修复，新增实际内置 WA-JS 消息准备兼容处理。

## 已复现与修复

- 群组清单读取：备用 `getMyUserLid()` 调用移除的原生接口，导致其他接口已确认身份时仍整次失败。身份读取已隔离异常，并保持账号匹配检查。
- 群发文字及媒体准备：SDK `prepareRawMessage`、`generateMessageID` 共用的 LID getter 仍调用移除的 `getMeLidUserOrThrow`。构建时仅适配应用内置库，优先使用原生 `getMaybeMeLidUser`；旧原生版本保留旧接口；缺少有效 LID 则阻止准备，不使用电话号码替代。
- FB 状态：包含已修复的序列化脚本打包与当前 Meta 登录界面识别。
- UI 验证脚本音量断言已与应用设定的 85% 对齐。

## 验证

新增测试从已锁定依赖的实际 SDK 分发表提取发送、准备、消息编号函数，以受控原生模块验证原库报错和适配后的成功路径。无需真实发送消息。构建检查还从 Windows app.asar 提取库，逐字核对其确实为经过测试的适配产物。

已有功能的回归包括：群发所选群组在账号内自下而上的顺序、定时与立即队列、文字和媒体、引用回复、提及、回执、未确认防重复、群组禁言与开放发言、进退群、限流冷却、账号与聚合会话分组顺序持久化、客户备注与标签、通知声音、FB 登录状态、代理及窗口恢复。Windows CI 执行完整类型检查、全部自动测试、安装升级测试和打包应用原生启动／恢复验证；发布只在这些步骤成功后执行。

范围：代码、受控页面与原生模块回归、Windows 打包检查，不等于已用用户真实账号完成所有业务操作。截图中的 `rate-overlimit` 是 WhatsApp 服务端限流，不能用兼容适配消除；程序仍冷却暂停并只读核验，避免重复提交。

不自动重发历史未确认消息，不替换正式版资产，Mac 发布暂停。
